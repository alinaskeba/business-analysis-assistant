# Порівняння зі зміною лише промпту — підготовка

- [База v5](baseline-v5/manifest.json): копія вже отриманої відповіді та конфігурації, SHA-256 кожного файлу; початкові артефакти не перезаписані.
- [Таблиця очікувань](expectations.draft.md): DRAFT, підготовлена за оригінальним брифом з командою, чекає ручного затвердження.
- Оцінювання бази за цією таблицею, новий промпт і живі порівняння ще не виконувалися: користувач визначив затвердження передумовою.

Після затвердження: оцінити v5 з доказами для кожного пропуску; додати лише до
промпту короткі приклади подвійного відображення дій у users/requirements і нейтрального
питання про конфлікт; лишити схему, валідатор, модель і брифи незмінними.
Порівнювати correctness, omissions, unsupported facts, а не лише кількість записів.

У репозиторії зараз є одне сімейство dev-брифів: переговорки без команди та з командою.
Це два варіанти в одному dev-спліті, а не незалежні задачі.
Для перевірки узагальнення потрібні додаткові dev-брифи з окремими чернетками
очікувань (зокрема чистий бриф без конфлікту та інший бізнес-процес).
Їх слід зафіксувати до перегляду нових відповідей; відкладені кейси не використовувати
для підбору промпту. Базовий промпт і новий кандидат запускати на однаковому наборі.
